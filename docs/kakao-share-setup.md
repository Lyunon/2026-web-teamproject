# 카카오톡 결과 공유

## 동작

결과 화면에 공유 미리보기와 카카오톡 공유 버튼을 추가했습니다.
카카오 JavaScript SDK 2.8.5의 Kakao.Share.sendDefault()를 클릭 이벤트 안에서 호출합니다.
초기 버전은 별도 대표 이미지가 필요 없는 기본 **텍스트 템플릿**입니다.
공유 항목: 닉네임, 사건 제목, 성공/실패, 결과 화면의 최종 점수, 소요 시간, 힌트 수.
범인, 해설, Firebase UID/이메일, 샘플 랭킹은 메시지에 포함하지 않습니다.
'나도 도전하기'는 https://2026-web-teamproject.vercel.app/ 를 엽니다.
공유받은 사람이 보낸 사람의 결과 상세 페이지를 조회하는 기능은 포함하지 않습니다.
게임 로그인은 Google 그대로이며 카카오 로그인 구현이나 Firestore 규칙 변경은 필요 없습니다.

## 카카오 앱 설정

- JavaScript 키는 public/js/kakao-share-data.js에 설정했습니다. 브라우저 공개용 키입니다.
- JavaScript SDK 도메인: https://2026-web-teamproject.vercel.app 와 http://localhost:3000
- 제품 링크 웹 도메인: https://2026-web-teamproject.vercel.app
- 다른 포트/127.0.0.1/Vercel Preview 주소를 쓰면 해당 SDK 도메인을 별도로 등록해야 합니다.
- Admin 키나 Client Secret을 프런트엔드에 추가하지 마세요.

## 테스트

```bash
node --test test/kakao-share.test.mjs
```

10개 테스트에서 메시지 값, 스포일러 제외, 실패 결과, 숫자 검증, 다른 계정/샘플 차단,
SDK 로드 실패 재시도, 직접 클릭 호출, 호출 오류 안내를 검사했습니다.
실제 SDK 서버/카카오 계정/메시지 전송은 모의 테스트로 검증되지 않습니다.

실제 확인 순서:
1. 새 버전에서 Google 로그인 후 게임을 한 번 완료합니다.
2. 결과 화면의 미리보기와 표시 점수가 일치하는지 확인합니다.
3. 카카오톡으로 결과 공유를 누릅니다.
4. 본인 대화방(나에게) 등을 직접 선택하여 전송하고 내용 및 '나도 도전하기' 링크를 확인합니다.
5. 모바일에서도 카카오톡 앱 전환을 확인합니다. PC에서는 카카오 계정 로그인 화면이 나올 수 있습니다.
6. 로컬 테스트 시 Gemini 설정/의존성은 기존 게임 실행 환경 그대로 준비해야 합니다.

SDK 호출만으로 실제 전송 완료를 알 수 없어 UI는 '공유 화면에서 대화방을 선택해 주세요'라고 표시합니다.
네트워크 오류 시 게임 결과는 계속 표시하고 공유 준비를 다시 시도할 수 있습니다.

## 기록과 점수

새 게임 결과에 playerUid를 추가해 현재 계정의 기록인지 확인합니다. 이전 버전에서 저장한 기록은
UID가 없어 공유되지 않으므로 적용 후 새로 플레이해야 합니다.
UID는 localStorage에서만 사용하며 공유 메시지/링크에 넣지 않습니다.
현재 결과 점수 산출 방식은 유지했습니다. 브라우저 기록은 수정 가능하므로 서버 검증 성적 인증 기능이 아닙니다.
실제 랭킹/점수 서버 검증 및 이미지형 피드 템플릿은 별도 작업입니다.

## 적용 기준

로컬에 저장된 main a3c0f16을 기준으로 작성했습니다.
GitHub Desktop에서 main의 최신 내용을 Pull한 뒤 feature/kakao-share 브랜치에 적용합니다.
서버의 최신 변경과 충돌하면 스크립트가 중단되므로 강제로 덮어쓰지 않고 차이를 확인합니다.
코드 적용/커밋/푸시/배포/실제 카카오 전송은 자동 수행하지 않았습니다.
