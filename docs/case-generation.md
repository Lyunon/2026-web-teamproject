# Gemini 사건 생성

사건 목록 → **✨ Gemini로 새 사건 생성** → 장르·난이도 선택 → **사건 생성하기**.

## 흐름
1. 브라우저가 `POST /api/generate { genre, difficulty }` 를 보낸다. (`genre`: mansion·gallery·train·random, `difficulty`: easy·normal·hard·expert)
2. 서버(`api/_lib/caseGenerator.js`)가 난이도 규칙을 프롬프트에 넣어 Gemini 에게 사건을 설계시키고, **같은 규칙으로 결과를 검증**한다. 규칙을 못 맞추면 자동으로 다시 만든다.
3. 정답이 든 사건 전체를 서버 키로 암호화(AES-256-GCM)한 `caseToken` 으로 돌려준다. 브라우저는 내용을 읽거나 바꿀 수 없다.
4. 브라우저는 토큰을 `localStorage`(`gen_cases_<uid>`)에 저장하고, `play.html?case=gen-xxxx` 에서 모든 API 요청에 같이 보낸다.

Vercel 서버리스는 파일·메모리가 유지되지 않아 DB 없이 이 방식을 쓴다. 대신 **다른 기기·브라우저에서는 생성 사건이 보이지 않는다.**

## 난이도 (`api/_lib/difficulty.js`)
| 항목 | 쉬움 | 보통 | 어려움 | 매우어려움 |
| --- | --- | --- | --- | --- |
| 용의자 수 | 3 | 4 | 5 | 6 |
| 시작 단서 | 3 | 3 | 3 | 2 (하나는 오해를 부름) |
| 숨은 단서 | 4~5 | 5~6 | 6~7 | 7~8 |
| 가짜(유도) 단서 | 1+ | 2+ | 3+ | 4+ |
| 진술 모순 | 1+ | 2+ | 3+ | 4+ |
| 범인의 거짓말 | 1+ | 2+ | 2+ | 3+ |
| 거짓말하는 무고한 용의자 | 0 | 1+ | 3+ | 4+ |
| 결정적 증거까지 단계 | 2+ | 3+ | 4+ | 5+ |
| 결정적 증거의 선행 단서 | 1+ | 2+ | 2+ | 3+ |
| 선행 조건이 걸린 규칙 | 1+ | 2+ | 3+ | 4+ |
| 질문(ask) / 단서 제시(show) 규칙 | 1/1 | 2/1 | 2/2 | 3/2 |
| 힌트 | 거의 직접 | 방향 위주 | 모호 | 아주 모호 |
| 심문 AI 태도 | 증거에 쉽게 인정 | 기본 | 한 번에 무너지지 않음 | 한 번 더 둘러대고 진실을 섞음 |

## 테스트
`npm run test:generate` — Gemini 를 호출하지 않고 검증기, 토큰, API 흐름을 확인한다.
